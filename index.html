Three keystrokes, any app

Pressto reads the description of the screen that macOS builds for VoiceOver, so it works in apps that were never designed for it — native apps, Electron apps and web pages alike.

Open

⇧⌘H opens the palette over the window you're using. The list fills in within a fraction of a second.

Type

Initials, part of a word or part of a web address. Results re-rank with every key; ↑ ↓ move the selection.

Press

↵ brings the app back to the front and presses the item. Text fields get the focus; buttons that refuse a direct press get a real click.

What you can reach

Everything goes into one list. With an empty search it is grouped by section; as you type it becomes a single ranked list.

🪟

Window controls

Buttons, links, checkboxes, pop-ups, sliders and text fields that are visible in the front window, including the buttons of a sheet or dialog on top of it.

☰

Menu bar

Every enabled item of the app's menus, shown with its path (History › Recently Closed Tabs), without opening them one by one.

🗂️

Browser tabs

Switch tabs by title — or by address in Safari, Chrome, Brave, Edge, Vivaldi, Firefox and Zen, so a PR number or a hostname finds its tab.

⚡

Quick actions

On a web page: copy its address, its title, or a ready-made Markdown link.

Narrow the search

Start with a symbol (or a word followed by a colon) to search a single section.

@ or tab:Browser tabs, by title or address — @ pull 112
# or win:Controls of the front window
/ or menu:The menu bar
> or do:Quick actions

↑ ↓ or ⌃P ⌃N to move · ↵ to press · ⎋ to close

What it can't reach

Pressto only knows what an app tells macOS. A few things fall through:

  • Unnamed icon buttons. A button with no title or description has nothing to type, so the palette leaves it out. Use hint labels (⇧⌘J) for those.
  • Things off screen. Only what is visible in the front window is listed — scroll first. Browser tabs are the exception: the whole tab list is searchable.
  • Typos. The search forgives missing letters, not wrong ones: mrege won't find Merge.
  • Apps with poor accessibility. Games, some cross-platform toolkits and canvas-drawn apps describe little or nothing to macOS. The keyboard grid (⇧⌘K) still works there.

Get Pressto

There is no release yet. Building it takes a couple of minutes and needs Xcode.

  1. Clone the source and build it: 
    git clone https://github.com/nillebco/pressto.git
cd pressto
scripts/dev
    scripts/dev builds the app, signs it with your Apple Development certificate if you have one, and launches it.
  2. When macOS asks, give Pressto Accessibility access in System Settings → Privacy & Security → Accessibility. Until you do, its menu bar icon is red, and its menu offers a shortcut to that settings page.
  3. Optionally, move or link .build/Build/Products/Debug/Pressto.app into Applications so Spotlight and launchers find it.

A signed, notarized download will replace these steps. Watch the repository to hear about it.

Questions

Why does Pressto ask for Accessibility access?

That permission is how one app can see and press another app's buttons; VoiceOver and every window manager use it too. Pressto uses it only for that. It collects nothing and makes no network requests.

I granted access, but the icon is still red.

macOS ties the permission to the app's signature. A build signed without a certificate (ad-hoc) gets a new signature each time it is rebuilt, so the old permission stops matching. Remove Pressto from the Accessibility list, add it again, or build with scripts/dev, which signs with your Apple Development certificate so the permission survives rebuilds.

Why does it ask to control my browser?

The first time you open the palette over Safari, Chrome, Brave, Edge or Vivaldi, macOS asks whether Pressto may control that browser. Saying yes lets it read the address of each tab when you open the palette, so you can find a tab by part of its address. Saying no is fine: tabs are still listed by title. You can change it in System Settings → Privacy & Security → Automation. Firefox and Zen don't ask: Pressto reads the session file they keep on disk. Either way, nothing leaves your Mac.

A web page shows only its menu items.

Firefox, Zen and Chromium-based apps build their accessibility description only when an assistive tool asks for it. Pressto asks when the palette opens and searches again while the page fills in, so the window's controls can arrive a second later on the first try.

Can I change the shortcuts?

The hint, grid and free-cursor shortcuts can be changed in Pressto's Settings. The palette shortcut is fixed at ⇧⌘H for now.

Can I still point at things the old way?

Yes. Pressto keeps Scoot's hint labels (⇧⌘J), keyboard grid (⇧⌘K) and free cursor movement (⇧⌘L) for anything without a name.

Why isn't it on the Mac App Store?

App Store apps run in a sandbox that forbids pressing other apps' buttons, which is the whole point of Pressto. It will ship as a signed, notarized download instead, like most keyboard tools for the Mac.

Where does it come from?

Pressto is built on Scoot by Michael Russo, an open-source keyboard cursor tool under the BSD 3-Clause licence. The palette is new; fixes that help Scoot too are sent back upstream.
